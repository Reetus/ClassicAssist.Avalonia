# Hotkey command TODO

Gap between this repo and the WPF `ClassicAssist` tree. Generated by comparing every
`[HotkeyCommand]`-attributed class in both trees.

- **78 hotkey commands upstream, 69 here**
- **9 missing** (13 as of writing; `Grid Container Viewer`, `All Names`, `Object Inspector` and
  `Use Last Skill` have since been ported)
- No command here is absent upstream, and no signature has drifted - the gap is purely
  commands that were never ported.

Names below are the `Name =` on the attribute, which is also the resource key. Every one of
them already has an entry in `Strings.resx`, so nothing here needs a new string.

## Blocked on missing macro commands

These hotkeys are thin wrappers over macro commands this repo does not have. See
`MACRO_COMMANDS_TODO.md` - porting the command makes the hotkey trivial.

- [ ] **Toggle Autoloot** (`ToggleAutolootCommand.cs`) - needs `AgentCommands.SetAutoloot`.
- [ ] **Toggle Scavenger** (`ToggleScavengerCommand.cs`) - needs `AgentCommands.SetScavenger`.

      Both are more than a copy: upstream drives `AutolootManager` / `ScavengerManager` through
      `SetEnabled( bool )` / `IsEnabled()`, and **neither manager here has those methods**. The
      enabled flag has to be given a home on the manager first, otherwise the hotkey has nothing
      to toggle.

- [ ] **Take Snapshot** (`SnapshotCommand.cs`) - needs `MainCommands.Snapshot`, which returns
      `(bool, string)` and is absent here. Upstream captures the client window through the host,
      so this is really a plugin-side capability question, not just a missing method.

## Blocked on configurable-hotkey infrastructure

- [ ] **Greater Heal / Cure Self** (`GreaterHealCureSelf.cs`)
- [ ] **Mini Heal / Cure Self** (`MiniHealCureSelf.cs`)

      The command bodies port as-is - `MobileCommands.Poisoned` and `SpellCommands.Cast` both
      exist here. What is missing is the mechanism that lets a hotkey carry settings:

      - `HotkeyConfigurationAttribute` (upstream `Data/Hotkeys/HotkeyConfigurationAttribute.cs`)
        has no counterpart here.
      - `HotkeyEntry.Configurable` does not exist here, so `HotkeysTabViewModel` has no configure
        command and the Hotkeys tab has no UI to reach one.
      - The `CureType` enum these two share (`Cure` / `ArchCure`) also needs porting.

      Worth doing as one piece of work rather than per command - it is the only reason these two
      are blocked, and it unlocks any future configurable hotkey.

## Blocked on a missing window

- [ ] **Show Chat Window** (`ShowChatWindowCommand.cs`) - needs a `ChatWindow` view. Not ported.
- [ ] **Show GIF Capture** (`ShowGIFCaptureWindow.cs`) - needs a `GIFRecorderWindow` view. Not

      `EntityCollectionViewerHotkey` does.

## Notes for whoever picks this up

- A hotkey's `Name` is looked up in `Strings.ResourceManager` by `HotkeyCommand`'s constructor and
  falls back to the literal if absent, so a typo shows up as an untranslated string rather than an
  error. Check the key exists.
- An empty `Category` puts the command under `Commands` in the tree, not in a blank group.
- Commands are discovered by reflection over `Assembly.GetExecutingAssembly()` in
  `HotkeysTabViewModel.Deserialize`, so a new file in `Data/Hotkeys/Commands/` is picked up with no
  registration step.
- `Execute()` runs on a thread pool thread (`Action = hs => Task.Run( Execute )`). Anything that
  touches the UI has to go through `Engine.UIInvoker`, and anything that blocks on a target or a
  packet wait is fine there.
